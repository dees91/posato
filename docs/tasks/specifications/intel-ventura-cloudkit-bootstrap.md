# Intel Ventura CloudKit bootstrap timeout

- **Record path:** Recorded task
- **Review tier:** High-risk, because changing the CloudKit request deadline affects account-bound bootstrap and unknown-outcome handling.
- **Outcome:** Determine why the notarized Intel Ventura candidate repeatedly reports that iCloud sync did not finish, and deliver a verified correction if the application's 30-second deadline is the cause.
- **Boundary:** Preserve the existing Apple Account, Keychain, CloudKit workspace, local database, and pending operations. Do not remove or recreate a workspace, sign out, alter account settings, or log identifiers or payloads. Keep the existing bootstrap protocol and account-binding checks.
- **Dependencies:** ADR 0007 and the existing signed Intel Ventura candidate; the macOS sync companion's 120-second protocol maximum.
- **Acceptance:** A controlled read-only diagnosis identifies the stage and failure class. Before replacing the app, confirm no active session, proxy ownership, bootstrap attempt, or sync companion; quit Posato, preserve the exact installed signed candidate for rollback, and verify the replacement's signature and entitlements. If the 30-second local cutoff is the cause, a bounded deadline change permits bootstrap on the same MacBook without changing data or security semantics. If a longer request still fails, restore the prior installed signed app and source deadline without touching the local database, Keychain, CloudKit workspace, or pending attempt. Verify account-bound local state, proxy/helper readiness, and sync result without relying on the generic UI message alone.
- **Verification:** Use the existing physical failure as the pre-change E2E regression; capture a repeatable ignored evidence record with revision, target, initial state, command/action, observed result, and limits. Run focused build and quality checks, package a signed candidate, then verify the real app on the explicitly authorized Intel MacBook. Keep raw logs under ignored `build/verification/`.
