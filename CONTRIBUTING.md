# Contributing to Posato

Thank you for your interest in Posato.

## Issues

Bug reports, questions, and ideas are welcome in
[GitHub Issues](../../issues). Before opening one, please search existing issues.

Keep reports free of personal data. Do not include website names, app names,
device names or models, account details, screenshots, or logs; describe the
problem with synthetic examples such as `example.com` instead. Security
vulnerabilities belong in a private report, as described in the
[security policy](SECURITY.md).

## Pull requests

Pull requests are not accepted at the moment. Please open an issue instead; if
the project starts accepting contributions, this document will describe how.

## Working with the code

The [development guide](docs/development/README.md) explains the toolchain,
local quality gate, and verification tools. Project decisions and working rules
are in the [task workflow](docs/tasks/README.md), the
[engineering quality contract](docs/development/engineering-quality-contract.md),
and [AGENTS.md](AGENTS.md).
